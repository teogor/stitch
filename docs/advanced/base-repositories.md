# Using Base Repositories

In large applications, you often have shared logic or common function signatures across all your repositories. Stitch allows you to enforce a base interface or class for all generated repositories using the `repositoryBaseClass` configuration.

---

## 🛠️ The Problem

You might want all your repositories to implement a common interface for generic handling, logging, or error tracking:

```kotlin
interface BaseRepository {
    val repositoryName: String
}
```

Manually adding this to every generated repository would be tedious and error-prone.

---

## ✨ The Stitch Solution

You can specify a `repositoryBaseClass` in your Gradle configuration. Stitch will ensure all generated repository interfaces extend this base class.

### 1. Define your Base Interface

```kotlin
package com.myapp.data

interface AppRepository {
    fun clearCache()
}
```

### 2. Configure Stitch

In your module's `build.gradle.kts`:

```kotlin
stitch {
    repositoryBaseClass = "com.myapp.data.AppRepository"
}
```

### 3. Generated Result

Stitch will generate your repository interfaces as follows:

```kotlin
// Generated by Stitch
interface UserRepository : AppRepository {
    // ... generated functions
}
```

---

## 📦 Generic Base Repositories

If you use a generic base repository pattern, you can still use Stitch effectively. While Stitch currently targets specific entity-based repositories, having them extend a base interface allows you to write generic utilities that operate on any repository in your system.

### Example: Repository Registry

```kotlin
class RepositoryRegistry(
    private val repositories: List<AppRepository>
) {
    fun clearAllCaches() {
        repositories.forEach { it.clearCache() }
    }
}
```

---

## 🎯 Use Case: Domain Layer Abstraction

By using a `repositoryBaseClass`, you can ensure that your data layer strictly adheres to the requirements of your domain layer, even when the implementation is automated by Stitch.
